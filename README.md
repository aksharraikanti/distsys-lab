# distsys-lab

A slow, deliberate, ten-stage distributed systems learning track. Each stage builds
directly on the ones before it: by the end this is one compounded system — replicated,
sharded, transactional, cached, autoscaling, edge-fronted — deployed for real on AWS.

Design doc: see `~/.gstack/projects/code/aksharraikanti-unknown-design-20260907-140154.md`
(generated by `/office-hours`).

## How this repo works

- One stage per top-level directory, numbered in build order.
- Each stage has its own `README.md` (concept notes, filled in as I learn them, plus
  reference links) and `TASKS.md` (a day-by-day checklist, ~30-90 min per day).
- `PROGRESS.md` at the root always reflects where I currently am.
- One commit roughly per working day. Small, reviewable, working increments — not big
  batched drops.
- CI (`go test ./...`) runs on every push.

Later stages import earlier stages as local Go packages (directory names carry a
numeric prefix for ordering, e.g. `01-raft/`, but each directory's package name is the
plain word — `package raft` — since Go identifiers can't start with a digit).

## Stages

| # | Stage | Core Concepts |
|---|---|---|
| 1 | [Raft consensus from scratch](01-raft/) | Leader election, log replication, safety |
| 2 | [Fault-tolerant KV store on Raft](02-kv-store/) | Linearizability, snapshotting |
| 3 | [Connection pooling layer](03-connection-pooling/) | Pool sizing, backpressure, reuse vs cold-start |
| 4 | [Caching layer](04-caching/) | Cache-aside vs write-through, TTL/eviction, invalidation |
| 5 | [Sharded KV store](05-sharded-kv/) | Shard reconfiguration, migration, conflict serializability |
| 6 | [Hot shard detection + splitting](06-hot-shard-splitting/) | Load-based splitting, consistent hashing |
| 7 | [Distributed transactions](07-distributed-transactions/) | 2PC, MVCC, cross-shard atomicity |
| 8 | [Scale-to-zero orchestrator](08-scale-to-zero/) | Idle detection, cold-start latency, autoscaling |
| 9 | [CDN-backed edge layer](09-cdn-edge/) | Edge caching, invalidation propagation, origin shielding |
| 10 | [Eventual-consistency system](10-eventual-consistency/) | Vector clocks, CRDTs, gossip |
| — | [Capstone: mini distributed database on AWS](capstone/) | Combines 1-9, deployed on EC2/ECS + ElastiCache + S3/CloudFront |

Only Stage 1 is currently broken into daily tasks — later stages get scoped the same
way once they're reached, rather than front-loading a full day-by-day plan now.
